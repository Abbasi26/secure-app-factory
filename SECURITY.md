# Security

## Reporting a vulnerability

Open a private security advisory on this repository. Please include the version, the manifest or function involved, and a way to reproduce the issue without sending secrets, tenant data, or a live installer that you are not allowed to share.

## What this project does

Secure App Factory checks the installer you pointed it at before it wraps that file. A build fails when the SHA-256 does not match the manifest or the lock file, when those two pins disagree, or when the Authenticode policy fails. On a non-Windows host, Authenticode is reported as unavailable and a manifest that requires a signature fails closed.

`-TrustOnFirstUse` writes `lock.json` only when no pin exists yet and the signature policy already passed. It does not overwrite a pin.

Downloads are limited to https URLs without embedded credentials, with a size cap. Zip extraction refuses entries that leave the destination directory.

## What this project does not do

- It is not a malware scanner, a reputation service, or a claim that a matching hash means the vendor's build is safe.
- It does not check a timestamp counter-signature. The Notepad++ pin is the leaf certificate thumbprint from `Get-AuthenticodeSignature`. A renewal fails the build until someone reviews the new certificate and updates the pin.
- It does not install the Evergreen module, PSAppDeployToolkit, or the Win32 Content Prep Tool unless the caller asks for the last two by switch. Evergreen must already be installed.
- It does not create an Intune assignment, a MECM application, a dependency, or a supersedence relationship.
- It does not phone home. There is no telemetry.

## Intune secrets

Upload uses the client-credentials flow. Set these environment variables in the GitHub Actions secret store, or pass them as parameters. Do not commit them.

| Name | Purpose |
| --- | --- |
| `SAF_INTUNE_TENANT_ID` | Entra ID tenant id or tenant domain |
| `SAF_INTUNE_CLIENT_ID` | Application (client) id |
| `SAF_INTUNE_CLIENT_SECRET` | Client secret |

The app registration needs the application permission `DeviceManagementApps.ReadWrite.All` with admin consent. That permission can create and change Intune apps. Use a dedicated app registration. v0.1 sends the secret to `https://login.microsoftonline.com` and does not write it to `result.json`, `intune-plan.json`, or `REPORT.md`. The returned object also omits it. Avoid a transcript or trace session around `Send-IntunePackage` if your host would record request bodies.

The upload job in `.github/workflows/package.yml` runs only for a manual dispatch with the `upload` input set to true. If any of the three secrets is missing, no Graph call is made and the job fails.

## Third-party code

`Invoke-AppDeployToolkit.ps1` generated by this module is MIT. A folder built with `-IncludeToolkit` also contains PSAppDeployToolkit 4.1.8, which stays under LGPL-3.0-or-later. `IntuneWinAppUtil.exe` is Microsoft software downloaded at build time and is not stored in this repository. See `PACKAGE-NOTICE.txt` inside a built package and `src/SecureAppFactory/data/external-tools.json` for the pinned URLs and hashes.
